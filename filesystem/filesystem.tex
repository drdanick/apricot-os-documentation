\section{Preamble}
The Apricot Filesystem is a simple Filesystem designed to met the many Apricos Architectural constraints. Although it lacks most basic features expected in modern filesystems (such as error recovery, linking, and permissions), it does provide the facility to abstract block-based Apricos disks into a
more familiar directory/file model.

\section{Disk geometry}

Disks can have a maximum of 32 tracks, each of which contain 64 sectors. One sector contains a total of 256 bytes.
This gives disks a total raw capacity of 512kb. It should be noted that the first track on any disk is reserved for boot code
and filesystem metadata, so the total amount of usable space is 496kb across 31 tracks.
The smallest allocation unit is 1 sector (or 256 bytes).

\section{Conventions}

\subsection{Track and sector numbers}

In this document, tracks and sectors are numbered from 1. A disk has tracks 1 to 32, and each track has sectors 1 to 64.

Wherever a track or sector number is stored on disk (in a directory entry or in file metadata), it is stored counting from 0,
so the stored value is one less than the number used in this document. For example, the root directory is in track 2, sector 1;
a directory entry pointing to it stores the track as 1 and the sector as 0.

\subsection{Byte order}

Numbers larger than one byte are stored little-endian: least significant byte first. For example, a file size of 1000
(0x03E8) is stored as the byte 0xE8 followed by the byte 0x03.

\section{Space Bitmap}

The bitmap uses one bit per sector on a disk. With '0' being used to show that the sector is free, and '1' to show that it is allocated.
Each group of 8 sectors is stored as a byte, with the Least Significant Bit representing the lowest sector,
and the Most Significant Bit representing the highest. Each subsequent byte in the bitmap represents a group of sectors
with a higher address than the last: the first byte covers sectors 1--8 of track 1, the second byte covers sectors 9--16 of track 1,
and the ninth byte covers sectors 1--8 of track 2. Each track takes 8 bytes, so the whole bitmap is 256 bytes: exactly one sector.

For instance, if 00000001 is the first byte of the bitmap, then track 1, sector 1 is allocated, while sectors 2--8 are free.

Track 1 is reserved (see below), so all of its sectors are always marked as allocated.

\section{Reserved Track Layout}

The first track of a disk (track 1) is reserved for both boot code, and disk metadata.

Sectors 1 to 62 are reserved for boot code, which can be virtually any executable code.

Sector 63, the second to last sector, is the space bitmap for this disk.

Sector 64, the last sector, is the volume information sector. It contains information pertaining directly to the disk. The first 4 bytes are always the sequence 0xC0, 0x30, 0x0C, 0x03. This represents the disk
signature, and must be present for the disk to be valid. The next 8 bytes form a string which represents the name of the disk. The last two bytes form the boot signature,
which must be 0xAA followed by 0x55 if the disk is bootable. The rest of the space on this sector is undefined, but reserved for later use.

\section{Directory Listings}

A Directory Listing is an array of 8 byte entries, with a maximum length of 32, so a listing fills exactly one sector.
Each element in this array corresponds to a 'Directory Entry'.

The root directory listing is stored in track 2, sector 1: the first sector after the reserved track.

Each entry represents either another Directory Listing, or a file. The most significant bit of the first byte of an entry is '1' if the entry
is in use. An entry whose most significant bit is '0' is free, and the rest of its bytes are ignored.
The second most significant bit of the first byte of an entry specifies whether the entry is executable
(1 if it is, 0 otherwise). Any entry may be marked executable, but tools may restrict which entries they allow to be marked.
The third most significant bit of the first byte of an entry specifies whether the entry is another Directory Listing or a file (0 and 1 respectively).
The 5 least significant bits of the first byte of an entry specify the track that the entry is in. The 6 least significant bits of the second byte specify the sector.
For a directory, this is the sector holding its listing; for a file, it is the file's metadata sector.

The next 6 bytes are the name of the entry. A name shorter than 6 bytes is padded with zero bytes; a 6 byte name has no terminating zero.
Names are unique within a directory. Tools may restrict names further; for example, the Apricot OS shell and the filesystem manager
convert names to upper case.

\section{Files}

A file is a sequence of non-filesystem data. Every file has one sector allocated for file metadata. The first two bytes of metadata specify the size of the
file in bytes, and up to 254 bytes to specify the track and sector number of each successive chunk of the file. Because this info takes 2 bytes to represent,
files have a maximum size of 31.75kb.

Each chunk is one sector, described by a pair of bytes: the track, then the sector. The pairs are in the order of the file's data, and the used pairs come first.
A pair whose track byte is 0 is unused, since no chunk can be in the reserved track (stored as track 0); the first unused pair ends the list.
A file of $n$ bytes uses $\lceil n / 256 \rceil$ chunks, and only the first $n$ bytes of the chunks are part of the file.

\section{Loading Disks}

Upon loading a disk, the filesystem driver must do two things:

\begin{enumerate}
    \item Probe the disk and page track 1, sector 64 into memory. This is the volume information sector.
        After paging, it must be copied to a non paging area of memory.
    \item Copy track 1, sector 63 into memory. This is the disk space bitmap.
        As before, this must be copied to a non paging area of memory.
\end{enumerate}

\section{Booting}

The job of the stage 1 bootloader is to load the first track, minus two sectors (sectors 1 to 62) of a disk into memory, then jump to the first loaded byte.
A disk is marked as bootable if and only if the last two bytes of the volume information sector (track 1, sector 64) are 0xAA followed by 0x55. Additionally, a stage 1 bootloader should
reject disks which do not contain the disk signature byte sequence 0xC0, 0x30, 0x0C, 0x03.
